# ADR-0001: ย้ายนัดแรกจาก v1 เข้า v2 และแขกเฉพาะนัด

**Status:** Accepted
**Date:** 2026-11-07
**Deciders:** หยก (เจ้าของโปรเจกต์)

## Context
นัดแรกกำลังใช้งานจริงบน v1 (8 คน ลงวัน เสนอร้าน และโหวตไว้แล้ว) ส่วนห้อง "แก๊งเรา" บน v2 สร้างแล้วและส่งลิงก์เชิญให้ทุกคนแล้ว
อยากให้นัดนี้อยู่ใน v2 ด้วย โดยที่หน้าตาดี ทำงานถูก และไม่พันกัน

v1 กับ v2 เก็บข้อมูลคนละแบบ:
- v1 ระบุตัวด้วยชื่อที่พิมพ์ และใคร ๆ ก็แก้ข้อมูลได้
- v2 ระบุตัวด้วย pid และมีสิทธิ์ตามบทบาท

แก๊งหลักคือ หยก ใหญ่ เบียร์ แนน ทราย ส่วน ณัฐ นอต แพร เป็นแขกเฉพาะนัดนี้

## Options Considered

| | A. v2 ดูข้อมูล v1 สด | B. ฝังหน้า v1 ใน v2 | C. เขียนสองทาง | **D. ย้ายเข้า v2 แล้วปิดเขียน v1** |
|---|---|---|---|---|
| ที่เก็บข้อมูลจริง | v1 | v1 | สองที่ | **v2 ที่เดียว** |
| หน้าตา v2 (สี, กรอบทอง, สุ่ม) | ดูได้ แก้ไม่ได้ | ไม่มี | ได้บางส่วน | **ได้ครบ** |
| ความซับซ้อน | กลาง | ต่ำ | สูง | กลาง (ทำครั้งเดียว) |
| ความเสี่ยงข้อมูลไม่ตรงกัน | ต่ำ | ไม่มี | **สูง** (ชื่อ↔pid, เขียนชนกัน) | ไม่มีหลังตัด |
| ต้องรื้อออกทีหลัง | ใช่ | ใช่ | ใช่ | ไม่ |

## Decision
เลือก **D**:
1. **ดึงข้อมูลเข้า** admin กดปุ่ม "ดึงข้อมูลจากลิงก์เดิม" ในห้อง v2 ระบบสร้างนัด id `v1` แล้วคัดลอกข้อมูลเข้ามา จับคู่คนด้วยชื่อ (ชื่อใน v1 ตรงกับชื่อในลิงก์เชิญ) กดซ้ำได้ ข้อมูลที่ถูกแทนที่มีแค่ของคนที่ยังไม่เคยแก้ใน v2 ทำให้ระหว่างรอตัด ทั้งสองลิงก์ยังใช้ได้
2. **ตัดลิงก์เดิม (cutover)** ทำเมื่อบอกแก๊งแล้ว ดึงข้อมูลรอบสุดท้าย แล้ว v1 จะกลายเป็นหน้าชี้ไป v2 และ rules ปิดการเขียน v1 งานนี้อยู่ใน branch `feature/v1-cutover` ยังไม่ merge
3. **แขกเฉพาะนัด** ใช้ field `meetId` บน members/invites เจ้าของหรือ co-host เป็นคนตั้ง แขกเห็นและแก้ได้แค่นัดนั้น และนับรวมแค่ในนัดนั้น นัดหน้าของแก๊งจึงนับแค่แก๊งหลัก ลิงก์เชิญเดิมใช้ต่อได้ ไม่ต้องสร้างใหม่

ไม่เลือก C เพราะต้องดูแลข้อมูลสองที่ตลอดเวลา และ v1 ไม่มีระบบสิทธิ์
ไม่เลือก A/B เพราะเป็นของชั่วคราวที่ต้องรื้อออก และไม่ได้หน้าตาใหม่จริง

## Consequences
- คนที่ยังไม่กดลิงก์เชิญจะขึ้นเป็นชิปสีจาง "ยังไม่เข้า" ในนัด ข้อมูลของเขาจะยังนับรวมอยู่ (เก็บชื่อกับสีไว้ใน `avail` ที่ดึงเข้ามา)
- ข้อมูล v1 เดิมยังอยู่ ไม่ได้ลบ ถ้าจำเป็นย้อนกลับได้ด้วย revert การตัด แล้วเผยแพร่ rules เดิม
- เจ้าของห้องที่เป็น admin เท่านั้นที่ดึงข้อมูลเข้าได้ (rules ตรวจ `admins/{uid}`)

## Action Items
1. [x] rules + เทส: admin ดึงข้อมูลเข้า, `meetId` บน members/invites
2. [x] UI: ปุ่มดึงข้อมูล, ตั้งแขกเฉพาะนัด, ชิปคนที่ยังไม่เข้า
3. [ ] เผยแพร่ rules → กดดึงข้อมูล → ตั้ง ณัฐ นอต แพร เป็นแขกนัด `v1` (ดู `docs/runbook-v1-cutover.md`)
