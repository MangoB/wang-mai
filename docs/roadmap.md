# Roadmap

ขอบเขต: `requirements.md` · security: `security.md` · หน้าตา: `design-system.md`

นัดแรก (v1, เข้าด้วยการพิมพ์ชื่อ) ใช้ต่อจนจบ งานระหว่างนั้นต้องไม่เปลี่ยนวิธีเข้าของ v1

## Phase 1 — ระหว่างนัดแรก

- [x] Firebase Emulator สำหรับพัฒนาในเครื่อง
- [x] ทดสอบ security rules บน emulator ทุกครั้งที่ push (`npm test`)
- [x] ทดสอบผ่านเบราว์เซอร์จริงแบบ end-to-end (`npm run test:e2e`)
- [x] App Check (reCAPTCHA Enterprise) ใน v1 และ v2
- [ ] Enforce App Check หลังดูกราฟ verified requests
- [x] v2 รุ่นทดลองที่ `/v2/`: ห้อง, guest, member Google, หลายนัด, ตั๋วทอง, สถานที่, สุ่มพร้อมหลักฐาน, สรุปนัด, ดูแลสมาชิก
- [ ] ทดลองใช้ v2 กับกลุ่มเล็ก

## Phase 2 — หลังนัดแรกจบ: ย้ายเข้า v2

1. ปุ่ม "นำเข้านัดแรก" สำหรับ admin (ทำงานในเบราว์เซอร์ผ่าน rules ไม่ใช้ service account key)
   - สร้างห้องแรก ให้เจ้าของเป็น owner
   - คนใน v1 แต่ละคน → invite (รหัสส่วนตัว + สีประจำตัว) ชื่อเดิม
   - นัดแรก → meetup ที่สรุปแล้ว พร้อมวันว่าง โหวต สถานที่ ผูกกับ `pid` ของแต่ละคน
2. ส่งลิงก์เชิญส่วนตัวให้ทุกคน
3. ลิงก์หลักเปิด v2, ปิดการเขียนของ v1 แล้วลบ `people`/`places` หลังตรวจว่านำเข้าครบ

## Phase 3 — รวมประวัติเข้าบัญชี

- member ที่ล็อกอิน Google ใส่รหัสส่วนตัวของตัวเองครั้งเดียว → บัญชีรับช่วง `pid` เดิม ประวัติ วันว่าง และโหวตตามมาครบ
- ถ้าทำรหัสหาย owner สร้างรหัสใหม่ให้ได้

## Phase 4 — รูปสถานที่

โปรเจกต์ Google Cloud แยก + เพดานรายวัน (ดู `security.md`) → ค้นชื่อร้าน รูปจริง และที่อยู่

## ภายหลัง

- ตั้งเวลานัด (ไม่ใช่แค่วัน)
- โอนความเป็นเจ้าของห้อง
- หน้า admin ภาพรวมทั้งระบบ
- แจ้งเตือนผ่าน LINE เมื่อสรุปนัด
