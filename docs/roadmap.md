# Roadmap v2

ขอบเขตอยู่ใน `requirements.md` · security ใน `security.md` · หน้าตาใน `design-system.md`

หลักใหญ่: **นัดแรก (v1) ใช้ต่อแบบเดิมจนจบ** — เพื่อนของเพื่อนยังเข้าด้วยการพิมพ์ชื่อได้ งานที่ทำระหว่างนั้นต้องไม่เปลี่ยนวิธีเข้าของ v1

## Phase 1 — ระหว่างนัดแรก (เพื่อนไม่รู้สึกถึงความต่าง)

1. **Firebase Emulator** สำหรับพัฒนาในเครื่อง + unit test ของ rules (v1 และ `firestore.v2.rules`)
2. **App Check ให้ v1** — ใส่ reCAPTCHA Enterprise แบบมองไม่เห็นในหน้าเว็บเดิม → ดูกราฟ verified requests → Enforce
   ผล: สคริปต์ภายนอกใช้ db ไม่ได้ ขณะที่เพื่อนยังพิมพ์ชื่อเข้าได้เหมือนเดิม
3. **สร้าง v2 ที่ `/wang-mai/v2/`** — ใช้ collection ชุดใหม่ (`rooms/...`) แยกจาก `people`/`places` ของ v1 โดยสิ้นเชิง
   ทดสอบกับกลุ่มเล็ก (เจ้าของ + เพื่อน 2–3 คน) ก่อนเปิดจริง

## Phase 2 — หลังนัดแรกจบ: ย้ายเข้า v2

1. **ปุ่ม "นำเข้านัดแรก" ในหน้า admin** (ทำในเบราว์เซอร์ของ admin ผ่าน rules — ไม่ใช้ service account key)
   - สร้างห้อง "แก๊งมหาลัย" ให้เจ้าของเป็น owner
   - แต่ละคนใน v1 → invite (รหัส guest + สีประจำตัว) ชื่อเดิม
   - นัดแรก → meetup ที่ "สรุปแล้ว" พร้อมวันว่าง/โหวต/สถานที่เดิม ผูกกับ `pid` ของแต่ละคน
2. ส่งลิงก์เชิญส่วนตัวให้ทุกคน (หน้าสมาชิกมีปุ่มคัดลอกทีละคน)
3. เปลี่ยนลิงก์หลักให้เปิด v2 · v1 ปิดการเขียน แล้วลบ `people`/`places` หลังตรวจว่านำเข้าครบ

## Phase 3 — Member + รวมประวัติ

1. ล็อกอิน Google, ตั้งชื่อ/สีเอง, จำห้องที่เคยเข้า
2. **รวมประวัติจากนัดแรกด้วยตัวเอง**: member ใส่รหัส guest ของตัวเองครั้งเดียว → บัญชีรับช่วง `pid` เดิม (ประวัติ วันว่าง โหวต ตามมาครบ) แล้วรหัส guest ใช้ไม่ได้อีก
   ไม่ต้องให้ admin แก้ db ทีละคน; ถ้าใครทำรหัสหาย owner กด "สร้างรหัสใหม่" ให้ได้
3. member สร้างห้องเองได้ (สูงสุด 5), co-host, เครื่องมือดูแลห้องครบ

## Phase 4 — รูปสถานที่

โปรเจกต์ Google Cloud แยก + เพดานรายวัน (ดู `security.md`) → ค้นชื่อร้าน, รูปจริง, ที่อยู่

## ภายหลัง

- ตั้งเวลานัด (ไม่ใช่แค่วัน)
- โอนความเป็นเจ้าของห้อง
- หน้า admin ภาพรวมทั้งระบบ
- แจ้งเตือนผ่าน LINE เมื่อสรุปนัด
